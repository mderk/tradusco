## Форма запроса

Сейчас фраза уходит парой `["текст", "контекст"]`, а промпт объявляет схему
`[["Phrase to translate", "context for the phrase"], ...]`.

Фраза становится объектом, у батча появляется общий блок словаря:

```json
{
  "glossary": [
    {"term": "Booty Chest", "mode": "stem", "t": {"pl": "...", "ko": "..."}}
  ],
  "phrases": [
    {
      "phrase": "Open the Booty Chest",
      "context": "Button on the reward screen.",
      "reference": {"ru": "Открой сундук с добычей"},
      "examples": [
        {"phrase": "Open the Daily Chest", "t": {"pl": "...", "ko": "..."}}
      ]
    }
  ]
}
```

Словарь общий на батч, а не на фразу: иначе перевод одного термина повторится
столько раз, сколько фраз в батче. Опорный перевод и примеры — на фразу, они у
каждой свои. Пустые поля не отправлять, а не отправлять пустыми.

`prompts/translation.txt` переписывается под эту схему, включая строку с
описанием входа. Снапшоты (`tests/test_prompt_snapshot.py`) обновляются осознанно
через `UPDATE_PROMPT_SNAPSHOTS=1`, дифф читается глазами.

## A2. Словарь

Файл `<project>/glossary.json`, формат — тот, что уже отработан в t3
(`/Users/max/Documents/projects/t3/client/translation_glossary.json`, 580 КБ):

```
{ "_": {...}, "terms": {...1027 авто...}, "manual": {...44 руками...} }
```

Запись: `{"t": {язык: перевод}, "group", "mode", "scope", "near", "cs", "source"}`.
Секции `terms` и `manual` читаются в один словарь, `manual` перекрывает `terms`.
Отсутствие файла — не ошибка, блок просто пустой.

Подбор — функция, которую вызывает переводящий код, не скрипт, дописывающий
термины в колонку контекста: колонка одна на все языки, а набор нужных записей
зависит от запроса.

Режимы (`_` в файле их и описывает):

- `exact` (934 записи) — срабатывает только на точное совпадение всей фразы с
  ключом, внутрь фразы не заглядывать;
- `stem` (93) — совпадение по основе внутри фразы, по границе слова, склонения
  допускаются;
- `keep` — не переводится, идёт в блок с этой пометкой;
- `skip` — не срабатывает никогда.

Флаг `cs` — сравнение с учётом регистра. Поле `near` — регулярное выражение,
которое должно найтись рядом с термином, иначе срабатывание ложное (`Chaos` как
фракция против `chaos` как слова).

Записи урезаются до языков запроса: `t` фильтруется, остальные языки не
отправляются. Записей в батч — не больше двадцати; если подобралось больше,
оставлять те, что срабатывают в большем числе фраз батча.

Поле `scope` в авто-секции пустое, а в ручной встречается (`ui`, `all`). Данных,
по которым можно отличить область строки, в CSV сейчас нет. Считать `scope`
неограничивающим, а факт записать в `WORKFLOW_NOTES.md` — не изобретать колонку.

Готово, когда: в собранном промпте видны термины именно этой фразы и переводы
именно запрошенных языков.

## A3. Опорные переводы

Параметр `--reference-langs ru,ja`, значения берутся из колонок CSV этих локалей.
Опорный язык не может быть языком запроса; пересечение — ошибка запуска.

В промпте отдельный блок с явной пометкой: источник — базовый язык, опорный
только снимает неоднозначность. Пустая ячейка означает отсутствие поля, а не
пустую строку.

Готово, когда: опорные переводы видны в снапшоте промпта, а их отсутствие для
строки не ломает запрос.

## A4. Примеры-соседи

Скелет строки: заменить сработавшие термины словаря на плейсхолдер. `Tina Pack` и
`Rayne Pack` дают один скелет. Индекс «скелет → ключи» строится перед прогоном по
той же CSV, отдельного источника не требует.

В примеры годится только строка, у которой перевод на язык запроса уже есть и
проходит валидацию. Две-три пары на фразу, при большем числе кандидатов брать
ближайшие по длине. Одиночная строка даёт пустой блок, и это нормально.

Готово, когда: для строки из серии однотипных в промпте появляются её соседи, а
для одиночной строки блок пуст.

## A5. Правила языка

Наполовину закрыто в A1: `<lang>/context.txt` читается по каждому языку прогона и
уходит в промпт под меткой `[код]`, код локали больше не приходит модели заглавным
(`uk` читался как United Kingdom).

Остаток: закрепить формат блока снапшотом на двух языках и проверить, что правила
одного языка не растекаются на другой. Кода это, скорее всего, не потребует.

Готово, когда: правила двух языков видны в одном промпте, каждое под своей меткой.

## Размер запроса

Обвязка растит вход, а A6 режет батч по оценке выхода и вход не считает — это
осознанно. Но словарь на двадцать записей, опорный перевод и по три примера на
фразу при батче в пятьдесят фраз дают заметный промпт. Померить реальный размер
собранного запроса на батче из t3 и записать в `BATCH_BASELINES.md` рядом с
остальными замерами. Если вход окажется сопоставим с выходом — вернуть входной
порог отдельным решением, не молча.

## Тесты

- термин `stem` срабатывает внутри фразы, `exact` — только на всю фразу;
- `near` не даёт ложного срабатывания, `cs` различает регистр;
- `skip` не срабатывает, `keep` попадает в блок с пометкой;
- `manual` перекрывает `terms` по тому же ключу;
- в блок словаря попадают только языки запроса;
- отсутствие `glossary.json` не ломает прогон;
- опорный язык, совпавший с языком запроса, — ошибка запуска;
- строка без опорного перевода и без соседей даёт запрос без этих полей;
- правила двух языков в одном промпте под своими метками.
